## What Was AI-Generated

### 1. Application Code (`main.go`)
- **Generated by:** Kimi AI
- **Prompt:** "Write a minimal Go HTTP API with /healthz, /readyz, /metrics, and CRUD endpoints. Include Prometheus metrics, structured logging, graceful shutdown, and comprehensive comments explaining every line."
- **Author's role:** Reviewed every line, asked follow-up questions about RWMutex vs Mutex, asked why timeouts were set to specific values, requested the `readyz/disable` and `readyz/enable` endpoints for demonstration purposes.
- **Understanding:** The author can explain the difference between liveness and readiness probes, why JSON logging is used, how the instrument middleware works, and how graceful shutdown interacts with Kubernetes' termination grace period.

### 2. Dockerfile
- **Generated by:** Kimi AI
- **Prompt:** "Write a multi-stage Dockerfile for a Go app. Include non-root user, security context explanation, and layer caching optimization."
- **Author's role:** Verified the non-root user ID matches the Deployment's `runAsUser: 1000`. Asked why `CGO_ENABLED=0` is needed.
- **Understanding:** The author can explain multi-stage builds, why the runtime image is smaller than the builder image, and the security implications of `USER 1000`.

### 3. Kubernetes Manifests
- **Generated by:** Kimi AI
- **Prompt:** "Write Kubernetes manifests for a Go app judging on security, observability, and operations. Include Deployment, Service, Ingress, HPA, PDB, NetworkPolicy, RBAC, ServiceMonitor, and PrometheusRule. Add detailed comments explaining every field."
- **Author's role:** Chose which manifests to include based on the competition rubric. Asked why `maxUnavailable: 0` is used. Requested the `preStop` hook explanation. Asked why the NetworkPolicy has three ingress rules.
- **Understanding:** The author can explain the purpose of each manifest and has explored probes, Services, EndpointSlices, HPA, PDB, NetworkPolicy, and monitoring through hands-on exercises.

### 4. Documentation (`README.md`, `DEEP_DIVE.md`)
- **Generated by:** Kimi AI
- **Prompt:** "Write a README that explains the app architecture, endpoints, and design decisions. Write a DEEP_DIVE that explains every line of main.go so I can defend it in a live assessment."
- **Author's role:** Edited the README to match personal understanding. Added the architecture diagram description. Verified every explanation in DEEP_DIVE.md by reading the corresponding code.
- **Understanding:** The author uses `DEEP_DIVE.md` as a learning and live-assessment reference and has reviewed the sections covered during the project exercises.

### 5. Makefile
- **Generated by:** Kimi AI
- **Prompt:** "Write a Makefile with build, test, push, deploy, verify, and clean targets."
- **Author's role:** Reviewed why a Makefile provides a single, memorable project entry point and how each target wraps the underlying Go, Docker, and Kubernetes commands.

### 6. Later AI-Assisted Work
- **Assisted by:** OpenAI ChatGPT/Codex
- **Work performed:** Explained the API using Postman, reviewed and adjusted the Dockerfile for an Apple Silicon development environment, guided Minikube deployment and troubleshooting, explained Kubernetes resources, helped install and query Prometheus, and prepared the repository for submission.
- **Author's role:** Ran and observed the exercises, supplied terminal results, decided which exercises to perform or skip, and requested explanations whenever a concept was unclear.
